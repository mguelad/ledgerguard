# ADR-012: PaymentIntent as payment aggregate

Status: Accepted

Source: implementation design v1.0, section 16.2.

## Decision

Use each PaymentIntent as one payment attempt. Resolve Charge and Checkout Session aliases to it.

## Consequences

Avoid charge double counting and support multiple attempts per order. Multiple distinct succeeded intents require duplicate-payment evaluation; a charge event does not create a new payment attempt.
