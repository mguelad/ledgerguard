# Database Recovery

Keep ingress, schedulers, notifications and workers stopped. Determine a recovery timestamp and inspect RDS LatestRestorableTime; record the expected data-loss interval. Restore to a new private RDS instance, verify encryption, parameter group, TLS hostname, roles and FORCE RLS, then use separate reviewed connection secrets. Do not point public services at it yet. Apply the durable external erasure ledger using `python manage.py replay_erasures --confirm-isolated-restore` under the maintenance role with temporary read access to the ledger prefix. Verify erased tenants have no rows/reports, run migrations if compatible, and test synthetic isolation plus a known evidence case. Perform overlap repair with alerts disabled, then restore one canary. Record actual RPO/RTO and do not claim the design target if the drill missed it. Preserve the old instance until rollback is no longer needed.
