# Notification Recovery

Check authoritative delivery status, provider ID, route activity, bounce/complaint and the notification/feedback queues. A delivery marked accepted means SES accepted it, not that the recipient read it. Do not re-enable a bounced or complained address until its owner and delivery issue are verified. During provider outage retain pending work and apply bounded retry/backoff; use reviewed replay only after the cause is corrected. Digest deliveries use the same tracking and recipient checks as single findings. A provider-acceptance/database-commit crash can repeat a message; preserve that evidence instead of claiming exactly-once delivery. Send a synthetic test through the verified configuration set and confirm delivery plus feedback handling before reopening notification traffic.
